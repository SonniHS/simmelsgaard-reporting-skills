# Composition rules — index (SAY, STRUCTURE, EXPRESS, CONDENSE)

> One line per rule of the IBCS Standards v2.0 composition part, in our own words, with the book
> page for citation. Rule IDs and short names are those of the Standards; summaries and the
> *(ours)* notes are ours (CC BY-SA 4.0, see the repository NOTICE).

Principles in one sentence each:
- **SAY** — convey a message: know the goal, introduce, deliver, support, summarise (pp. 77–86).
- **STRUCTURE** — organise content logically: consistent, non-overlapping, exhaustive,
  hierarchical (pp. 87–95).
- **EXPRESS** — choose the right chart or table, and replace misleading types (pp. 96–142).
- **CONDENSE** — put everything needed for the message on the page (pp. 143–156).

## SAY (SA)

| ID | Rule | p. | In short |
|---|---|---|---|
| SA 1 | Know objectives | 78 | Serve both the author's and the audience's goals. |
| SA 1.1 | Know own goals | 78 | Pick the goal level: inform (detection) < make understand (explanation) < get a decision (suggestion). |
| SA 1.2 | Know target audience | 78–79 | Know their role, knowledge and expectations — and who may disagree, and why. |
| SA 2 | Introduce message | 79 | Lead to the message: situation → complication → question. |
| SA 2.1 | Map situation | 79 | Start with facts and goals the audience already accepts. |
| SA 2.2 | Explain problem | 79–80 | Then the complication that matters to them. |
| SA 2.3 | Raise question | 80 | Phrase the question from the audience's side; the message answers it. |
| SA 3 | Deliver message | 80 | The key message answers the question. |
| SA 3.1 | Detect, explain, or suggest | 80–81 | A complete sentence; detections as precise as possible; explanations and suggestions add value. |
| SA 3.2 | Say message first | 82 | Message first, proof after; take care with bad news in live presentations. |
| SA 4 | Support message | 82 | Back the message up. |
| SA 4.1 | Provide evidence | 82–83 | The page itself proves the message with facts and figures. |
| SA 4.2 | Use precise words | 83 | Numbers instead of "significant", "relevant", "around". |
| SA 4.3 | Highlight message | 83–84 | Mark the cited facts in the visuals; pages without highlights tend to be statistics. |
| SA 4.4 | Name sources | 84 | Required in written reports, handouts and dashboards. |
| SA 4.5 | Link annotations | 84–85 | Numbered annotations, linked to the exact element, in free areas of the page. |
| SA 5 | Summarize message | 85 | Close a presentation with message and next steps. |
| SA 5.1 | Repeat message | 85 | End with the message in one sentence, not "thank you"; not needed in written reports. |
| SA 5.2 | Explain consequences | 86 | State the decisions requested and what follows from them. |

## STRUCTURE (ST)

| ID | Rule | p. | In short |
|---|---|---|---|
| ST 1 | Use consistent elements | 87 | Lists contain like with like. |
| ST 1.1 | Use consistent items | 87 | Items of one type only. |
| ST 1.2 | Use consistent types of statements | 87–88 | All detections, or all suggestions — not mixed. |
| ST 1.3 | Use consistent wording | 88 | Same grammar (e.g. imperative verb + noun for actions). |
| ST 1.4 | Use consistent visualizations | 88–89 | Symbols and icons in one style. |
| ST 2 | Build non-overlapping elements | 89 | Mutually exclusive elements. |
| ST 2.1 | Build non-overlapping reporting structures | 89–90 | Chapters and pages do not cover the same aspect twice. |
| ST 2.2 | Build non-overlapping business measures | 90 | No measure next to its own component on one level. |
| ST 2.3 | Build non-overlapping structure dimensions | 90–91 | No member next to a group that contains it. |
| ST 3 | Build collectively exhaustive elements | 91 | Cover the whole. |
| ST 3.1 | Build exhaustive arguments | 91 | No missing option or argument. |
| ST 3.2 | Build exhaustive structures | 91–92 | Elements add up to 100 %, usually via a remainder shown last after a gap. |
| ST 4 | Build hierarchical structures | 92 | A pyramid storyline. |
| ST 4.1 | Use deductive reasoning | 92–93 | Statement → comment → conclusion; for controversial calls to action; one weak link breaks it. |
| ST 4.2 | Use inductive reasoning | 93 | Parallel, homogeneous MECE arguments supporting one message; the robust default. |
| ST 5 | Visualize structure | 93 | Make the hierarchy visible. |
| ST 5.1 | Visualize structure in reporting | 93–94 | Outlines, summaries, navigation tabs. |
| ST 5.2 | Visualize structure in tables | 94 | Hierarchy visible in rows and columns (bold subtotals, totals, spacing). |
| ST 5.3 | Visualize structure in notes | 94–95 | One numbered note per line, numbers in a margin. |

## CONDENSE (CO)

| ID | Rule | p. | In short |
|---|---|---|---|
| CO 1 | Use small elements | 143 | As small as still legible. |
| CO 1.1 | Use small fonts | 143 | No oversized fonts. |
| CO 1.2 | Use small components | 143–144 | Big components are not easier to read. |
| CO 1.3 | Use small visuals | 144 | Smaller visuals leave room for context. |
| CO 2 | Maximize use of space | 144 | Fill wasted space with useful context. |
| CO 2.1 | Use narrow page margins | 144–145 | Corporate wide margins waste space. |
| CO 2.2 | Reduce empty space | 145 | In layouts and inside visuals; keep whitespace that structures. |
| CO 3 | Add data | 145 | More data raises density. |
| CO 3.1 | Add data points | 145–146 | 36 months read as fast as 12 and show more. |
| CO 3.2 | Add dimensions | 146 | Two or more dimensions reveal relationships. |
| CO 4 | Add visual components | 146 | Combined charts are one entity: overlay, multi-tier, extended. |
| CO 4.1 | Show overlay charts | 147–149 | Shared category axis; integrated variances save space, but multi-tier reads better when space allows. |
| CO 4.2 | Show multi-tier charts | 149–150 | Tiers above (time) or right (structure); same unit ⇒ same scale; typical: base, Δ, Δ%. |
| CO 4.3 | Show extended charts | 151 | Average/benchmark on a virtual extension of the axis, same value axis. |
| CO 4.4 | Embed chart components in tables | 152 | Table bars and pins aligned to rows; sparklines only properly scaled; traffic lights ≤ 3 states. |
| CO 4.5 | Embed explanations | 152–153 | Explanations next to the element they explain (not in live slides). |
| CO 5 | Add visuals | 153 | A page is what can be read together; consistent notation and scaling matter even more. |
| CO 5.1 | Show small multiples | 153–154 | Same type and identical scale; up to about 25 plus "Others"; enlarge, don't rescale. |
| CO 5.2 | Show related charts on one page | 155–156 | Related measures only; ratio trees left → right, equal-size charts; scaling markers where scales differ. |
| CO 5.3 | Show chart-table combinations | 156 | The table adds complementary data, not the chart's numbers. |
| CO 5.4 | Show charts and tables in text pages | 156 | Visuals next to the sentence they support, each with a title. |

## Medium-dependent rules

| Rule | Written report, handout, dashboard | Live presentation |
|---|---|---|
| Sources (SA 4.4), footnotes (UN 2.5) | required | may be omitted |
| Annotations (SA 4.5), embedded explanations (CO 4.5) | use them | usually spoken |
| Repeat the message at the end (SA 5.1) | not needed | do it |
| Message first (SA 3.2) | always | take care with unwelcome news |
| Text and bullets (EX 3.2) | allowed in handouts | avoid text slides |

## Interactive reporting *(ours, grounded in IBCS)*

IBCS applies to static and interactive reporting alike; a "page" is also a screen (p. v). Our
operational rules — default state complete, filters in title line 1, dynamic messages detect
only, scale groups recomputed per filter context, filter rather than highlight, tooltips and
drill for depth only — are in the [SKILL.md](../SKILL.md) §6 and in
[page-patterns.md](page-patterns.md) §4.
