# The IBCS Power BI theme

Generated by `scripts/build_pbi_theme.py` from the IBCS design tokens (bundled default palette
plus your optional overrides). Schema: report theme schema 2.157 (as of 2026-10). Do not copy hex
values by hand: regenerate after any token change, and run `--check` in CI.

## Design goals

- Black and greys for data only: AC dark, PY light, PL white fill with a dark outline.
- Impact colours used only for variances: bright green (good), dark red (bad) and blue for
  neutral or ambiguous impact. IBCS fixes the hues and their meaning, not the exact codes: pick
  codes once for the organisation (token overrides) and keep them.
- One font family; no gridlines, no value axes, data labels on, legend off (label series
  directly), no backgrounds, borders or shadows (SI 1.2).

## What the generated theme sets

| Theme key | Value / source token | Why |
|---|---|---|
| `dataColors[0..2]` | AC, PY, PL fill; then the remaining stack greys | default series order = scenario order |
| `good` / `bad` / `neutral` | `color.variance.*` (CVD build: blue-green for good) | used by conditional formatting and the new card's reference labels |
| `maximum` / `center` / `minimum` | greys | gradients stay grey: colour is reserved for impact |
| `textClasses` | one family from `typography.family.powerbi`, token sizes | key message, title, labels, footnotes |
| `visualStyles."*"."*"` | background/border/shadow off, legend off, value axis off, no gridlines, labels on with display units "None" | IBCS defaults for every visual |
| `columnChart`, `barChart` | `categoryAxis.innerPadding` = (1 − 2/3) × 100 | 2/3 bar width for absolute measures |
| `clusteredColumnChart` / `clusteredBarChart` | `layout.clusteredGapOverlaps` + `clusteredGapSize` from `geometry.referenceOffsetRatio` | overlapped scenarios with offset |
| `lineChart` | stroke width, square markers, series labels at the line end | lines without legends |
| `waterfallChart` | increase/decrease = good/bad, total = AC, other = PY | best native approximation; Deneb for IBCS waterfalls |
| `pivotTable`, `tableEx` | light horizontal row rules, no vertical grid, no banding, bold totals, row subtotals at the bottom, `imageHeight` = one row (SVG cells) | IBCS tables |

Variants: `ibcs-pbi-theme.json` (standard), `-cvd.json` (colour-vision-deficiency adaptation),
`-bw.json` on request (`--variants standard,cvd,bw`). IBCS describes these as adaptations for
specific readers or for output without colour; whether to maintain all of them is your choice.

## What a theme cannot do

- PL outline per series, FC hatch, variance-axis notation, colour by polarity, scenario
  triangles, pins: per-visual `visual.json` formatting, Deneb or SVG (see
  [card-routes.md](card-routes.md)).
- Number formats: they belong to the measures (format strings, calculation-group format
  expressions), not to the theme.

## Applying it

Register the JSON as a custom theme resource in the report and reference it from `report.json`
(Microsoft's PBIR/theme skills cover the mechanics), or import it in Desktop via the Theme pane.
`--theme-overrides <fragment.json>` merges a Power BI-only fragment (for example `visualHeader`
settings) over the generated theme; never put colours there that a token already defines.
`--validate` checks against the schema and also flags unknown object or property names, which the
schema itself would allow.
